# FoodRx

A mobile-first web app that turns a set of overlapping medical conditions
(diabetes, hypertension, high cholesterol, etc.) into one reconciled,
safe-to-eat / avoid food list, generated by Gemini.

## Project structure

```
foodrx/
├── public/                  # Static site (served as Worker assets)
│   ├── index.html
│   ├── css/styles.css
│   ├── js/app.js
│   ├── manifest.webmanifest
│   ├── sw.js
│   └── assets/
│       ├── icon-192.png
│       ├── icon-512.png
│       └── og-image.png
├── src/
│   └── worker.js            # Cloudflare Worker: serves assets + /api/generate
├── wrangler.toml
└── README.md
```

## 1. Install Wrangler (if you don't have it)

```bash
npm install -g wrangler
wrangler login
```

## 2. Set your Gemini API key as a secret

Get a key from https://aistudio.google.com/app/apikey, then:

```bash
wrangler secret put GEMINI_API_KEY
```

Paste the key when prompted. It is stored encrypted by Cloudflare and is
never committed to the repo or sent to the browser.

## 3. Deploy

```bash
wrangler deploy
```

This publishes the Worker (which also serves `public/` as static assets)
to `https://foodrx.<your-subdomain>.workers.dev/`.

## 4. Deploying via GitHub sync instead

If you'd rather deploy through Cloudflare's Git integration:

1. Push this folder to a GitHub repo.
2. In the Cloudflare dashboard: **Workers & Pages → Create → Connect to Git**,
   pick the repo, and set the build output as-is (Wrangler config is
   auto-detected from `wrangler.toml`).
3. Add `GEMINI_API_KEY` under **Settings → Variables and Secrets** as an
   **encrypted** secret (not a plaintext variable).
4. Trigger a deploy — Cloudflare builds from `wrangler.toml` automatically.

## Notes

- `wrangler.toml` is already set to `name = "my-diet"`, matching the OG/share
  URL baked into `index.html` and `app.js`
  (`https://foodrx.suvadipchakraborty.workers.dev/`). If you deploy under a
  different Worker name or a custom domain, update those two files' URLs to
  match.
- The OG/share image is a **PNG** (`public/assets/og-image.png`, 1200×630)
  as required by WhatsApp/social link previews — SVG is intentionally not
  used there.
- `/api/generate` never caches in the service worker, so results are always
  freshly generated.
